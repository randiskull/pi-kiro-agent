# ACP Transport Implementation Plan

## Overview

Implement the ACP transport for pi-kiro, replacing TUI-scraping (`stream-adapter.ts`) with a
persistent `kiro-cli acp` child per cwd that communicates over NDJSON JSON-RPC 2.0. The new
transport runs behind `PI_KIRO_TRANSPORT=acp`; the chat transport remains the default.

This plan implements the design at `.rpiv/artifacts/designs/2026-07-31_17-59-51_acp-transport.md`.
The scaffolding (acp-session.ts, acp-transport.ts, acp-transport.test.ts, index.ts gate) already
exists from the design phase. Each phase hardens/completes its file against the final locked
decisions.

**Scaffold audit findings (pre-plan):**
- No `--agent-profile` assumption found in acp-transport.ts — tool mounting uses `session/new.mcpServers` ✅
- No `session/load` stub present — divergence always → `session/new` ✅
- Per-session bridge lifetime implemented on `AcpChild.bridge`, closed in `killChild` and divergence reset ✅
- `planAcpTurn` uses `acpSessionId` as `agentName` key — consistent with the registry's one-child-per-cwd model ✅
- Test count: 18 as specified ✅
- index.ts `PI_KIRO_TRANSPORT=acp` gate at commit 802a6a1 ✅
- **Gap noted**: parity suite does not yet assert mid-turn toolCall visibility (commit 802a6a1 behavior); Phase 3 addresses this.

```typescript
/**
 * ACP session manager for the kiro ACP transport.
 *
 * Tracks, per logical Pi conversation (keyed by (cwd, agentName) pair), the
 * kiro ACP session that mirrors it. Identity is anchored on the hash of the
 * sent message prefix — the same divergence-detection mechanism as
 * session-manager.ts, but without the snapshot-diff capture: ACP gives us
 * the sessionId directly from session/new.
 *
 * Sessions are per (cwd, agentName) pair so concurrent Pi conversations on
 * the same cwd but different agent profiles don't collide.
 */

import { createHash } from "node:crypto";
import type { Message } from "@earendil-works/pi-ai";

interface AcpSession {
	sessionId: string;
	cwd: string;
	agentName: string;
	/** Number of Pi messages already mirrored into the ACP session. */
	sentMessageCount: number;
	/** SHA-256 of messages[0..sentMessageCount] — append anchor / divergence guard. */
	prefixHash: string;
}

const MAX_SESSIONS = 64;
const sessions: AcpSession[] = [];

export interface AcpTurnPlan {
	mode: "fresh" | "resume";
	/** ACP sessionId — set iff mode === "resume". */
	acpSessionId?: string;
	/** Delta start index: 0 for fresh (send full context), sentMessageCount for resume. */
	deltaStart: number;
}

// ─── Hash helpers (verbatim from session-manager.ts) ──────────────────────────

function messageText(content: Message["content"]): string {
	if (typeof content === "string") return content;
	return content
		.map((block) => {
			if (block.type === "text") return block.text;
			if (block.type === "toolCall") return `toolCall:${block.name}:${JSON.stringify(block.arguments ?? {})}`;
			if (block.type === "image") return "[image]";
			return "";
		})
		.filter((piece) => piece.length > 0)
		.join("\n");
}

function messageKey(message: Message): string {
	const toolName = (message as { toolName?: string }).toolName ?? "";
	return message.role + "\x00" + toolName + "\x00" + messageText(message.content);
}

/**
 * Deterministic, thinking-insensitive SHA-256 hash of a message sequence.
 * Uses SOH (\x01) as the inter-message delimiter — distinct from the \x00
 * field separator in messageKey, preventing crafted content from mimicking
 * a message boundary.
 */
export function hashMessages(messages: Message[]): string {
	const hash = createHash("sha256");
	for (const message of messages) {
		hash.update(messageKey(message));
		hash.update("\x01");
	}
	return hash.digest("hex");
}

// ─── Registry ─────────────────────────────────────────────────────────────────

function upsert(session: AcpSession): void {
	const existing = sessions.findIndex((s) => s.sessionId === session.sessionId);
	if (existing >= 0) {
		sessions[existing] = session;
	} else {
		sessions.push(session);
		if (sessions.length > MAX_SESSIONS) sessions.shift();
	}
}

// ─── Public surface ───────────────────────────────────────────────────────────

export function planAcpTurn(cwd: string, agentName: string, messages: Message[]): AcpTurnPlan {
	for (let i = sessions.length - 1; i >= 0; i--) {
		const session = sessions[i];
		if (session.cwd !== cwd || session.agentName !== agentName) continue;
		if (messages.length < session.sentMessageCount) continue;
		if (hashMessages(messages.slice(0, session.sentMessageCount)) !== session.prefixHash) continue;
		const delta = messages.slice(session.sentMessageCount);
		if (!delta.some((m) => m.role !== "assistant")) return { mode: "fresh", deltaStart: 0 };
		return { mode: "resume", acpSessionId: session.sessionId, deltaStart: session.sentMessageCount };
	}
	return { mode: "fresh", deltaStart: 0 };
}

export function recordAcpSession(
	cwd: string,
	agentName: string,
	acpSessionId: string,
	messages: Message[],
): void {
	upsert({
		sessionId: acpSessionId,
		cwd,
		agentName,
		sentMessageCount: messages.length,
		prefixHash: hashMessages(messages),
	});
}

export function advanceAcpSession(acpSessionId: string, messages: Message[]): void {
	const session = sessions.find((s) => s.sessionId === acpSessionId);
	if (!session) return;
	session.sentMessageCount = messages.length;
	session.prefixHash = hashMessages(messages);
}

export function dropAcpSession(acpSessionId: string): void {
	const index = sessions.findIndex((s) => s.sessionId === acpSessionId);
	if (index >= 0) sessions.splice(index, 1);
}

export function _resetAcpSessions(): void {
	sessions.length = 0;
}
```

```typescript
// Addition to the "tool-call events" describe block in acp-transport.test.ts:

it("tool_call events surface in partial message content during the turn (commit 802a6a1 parity)", async () => {
	const child = new AcpScriptChild();
	spawnMock.mockImplementationOnce(() => child);

	void (async () => {
		// Handshake
		const initReq = (await child.awaitLine()) as { id: number };
		child.sendLine({ jsonrpc: "2.0", id: initReq.id, result: { protocolVersion: 1,
			agentCapabilities: { loadSession: true, mcpCapabilities: { http: true, sse: false },
			sessionCapabilities: {}, auth: {} }, authMethods: [], agentInfo: { name: "Kiro", version: "test" } }});
		const sessionReq = (await child.awaitLine()) as { id: number };
		child.sendLine({ jsonrpc: "2.0", id: sessionReq.id, result: { sessionId: "sess-live1",
			modes: { currentModeId: "kiro_default", availableModes: [] },
			models: { currentModelId: "auto", availableModels: [] } }});
		child.sendLine({ jsonrpc: "2.0", method: "_kiro.dev/commands/available",
			params: { sessionId: "sess-live1", commands: [] }});
		const promptReq = (await child.awaitLine()) as { id: number };
		child.sendLine({ jsonrpc: "2.0", method: "_kiro.dev/metadata",
			params: { sessionId: "sess-live1", contextUsagePercentage: 1.0 }});
		// Emit tool_call BEFORE the session/prompt response
		child.sendLine({ jsonrpc: "2.0", method: "session/update", params: { sessionId: "sess-live1",
			update: { sessionUpdate: "tool_call", toolCallId: "tooluse_live1", title: "Running: @mcp/live_tool",
				rawInput: { q: "test" }, _meta: { kiro: { toolName: "live_tool", mcpServerName: "mcp" } } }}});
		child.sendLine({ jsonrpc: "2.0", method: "session/update", params: { sessionId: "sess-live1",
			update: { sessionUpdate: "agent_message_chunk", content: { type: "text", text: "done" }}}});
		child.sendLine({ jsonrpc: "2.0", method: "_kiro.dev/metadata", params: { sessionId: "sess-live1",
			contextUsagePercentage: 1.5, meteringUsage: [{ value: 0.01, unit: "credit" }], turnDurationMs: 500 }});
		child.sendLine({ jsonrpc: "2.0", id: promptReq.id, result: { stopReason: "end_turn" }});
		child.end();
	})();

	const events: AssistantMessageEvent[] = [];
	const stream = makeStreamViaAcp({ binaryPath: "kiro-cli" })(MODEL, { messages: [user("use live_tool")] }, undefined as never);
	let toolCallAppearedBeforeDone = false;
	let doneReached = false;
	for await (const event of stream) {
		events.push(event);
		if (event.type === "done") {
			doneReached = true;
		} else if (!doneReached && event.type === "thinking_delta") {
			// tool_call blocks are pushed to output.content synchronously in the session/update
			// handler; the next thinking_delta (from the following agent_message_chunk) carries
			// the updated partial — assert that partial contains a toolCall block
			// event.partial is directly accessible after the event.type === "thinking_delta" guard
			if (event.partial.content.some((b) => b.type === "toolCall")) {
				toolCallAppearedBeforeDone = true;
			}
		}
	}

	// Guard: at least one thinking_delta must have fired — if none fired, toolCallAppearedBeforeDone
	// would be vacuously false and the next assertion gives a misleading failure site
	expect(events.some((e) => e.type === "thinking_delta")).toBe(true);
	// toolCall block must be visible in a partial BEFORE the done event
	expect(toolCallAppearedBeforeDone).toBe(true);
	// And must still be in the final done event
	const done = events.find((e) => e.type === "done");
	expect(done?.type === "done" && done.message.content.some((b) => b.type === "toolCall")).toBe(true);
});
```

**Note on mid-turn visibility:** The `tool_call` session/update handler in `acp-transport.ts` pushes a `toolCall` block to `output.content` but does NOT call `stream.push()` with a partial update immediately. Mid-turn visibility is currently incidental — the toolCall block only appears in a partial when the **next** `agent_message_chunk` triggers a `thinking_delta` carrying the updated `partial`. This means if a tool_call arrives with no following text chunk before `session/prompt` resolves, the block never appears in any partial. A hardening fix would add an explicit `stream.push({ type: "thinking_delta", contentIndex: thinkingIndex, delta: "", partial: output })` after pushing the toolCall block in the `case "tool_call":` handler. That fix belongs in Phase 2 (`acp-transport.ts`); the test above is written to detect the current incidental case and can be tightened further once Phase 2 adds the explicit push.

## Performance Considerations

- Persistent child eliminates per-turn spawn overhead (~150-300ms cold start).
- Session reuse (delta prompt) eliminates full context resend on subsequent turns in the same conversation.
- Idle timeout (10 min) bounds resource usage for long-idle sessions.
- `discoverWorkflowMcpServers` runs once per turn (file system walk) — same as chat transport.

## Migration Notes

- Chat transport (`stream-adapter.ts`) remains the default. No migration required for existing users.
- To opt in: set `PI_KIRO_TRANSPORT=acp` in environment before launching pi.
- `session-manager.ts` remains for the chat transport; not touched by this plan.
