## Findings
- [D3] "resume branch of `resolveSession()`, so every turn takes the divergence": closing the bridge per turn and remounting it overturns the accepted decision in `docs/design/acp-transport.md` §5e.3 ("The bridge is mounted once (`acpEntry.bridge ??= ...`) and both the new-session and divergence branches reuse it"), which exists because kiro keeps the MCP client it built for the server named `pi` pointed at the first port it was told and "has no way to learn a new one" - so from turn 2 onward every bridged call hits a closed port, the exact live failure 5e.3 recorded. The spec never says it is superseding that decision. Fix: a new spec must either drop the per-turn close/remount and keep the child-scoped bridge (the `httpServer.unref()` change alone is what fixes the hang, as the spec itself states), or explicitly supersede §5e.3 with evidence that kiro rebuilds its MCP client from each `session/new` and update `docs/design/acp-transport.md` and the §5e.3 regression test accordingly.
- [D3] "The per-child bridge URL invariant (§5e.3) is preserved.": contradicted by the Approach, which advertises a new bridge URL in every turn's `session/new`. Fix: state one model of the bridge URL's lifetime and make Goal, Approach and Acceptance criteria agree.
- [D3] "   - The §5e.3 tests (one URL per child across a session reset) pass unchanged.": `test/acp-transport.test.ts` ("keeps one bridge URL across a divergence reset, so kiro never calls a dead port") asserts `calls` has length 1, `close` was never called and both sessions saw the same url; a per-turn close and remount makes all three false, and `test/acp-transport-live.test.ts` asserts the same `acpSessionId` across two turns, which removing the resume branch also breaks. Fix: list the tests the change rewrites, with the new expected assertions, instead of claiming they pass unchanged.
- [D3] "- Changing the idle-timeout default or the bridge URL lifetime model.": this item is placed out of scope as "Unchanged, no follow-up", yet the Approach changes the bridge URL lifetime model from child-scoped to turn-scoped. Fix: move the lifetime change in scope, or remove it from the Approach.
- [G1] "branch: it retires the session, mounts a fresh bridge through": removing the resume branch bypasses what the turn planner relies on for multi-turn conversations, and the spec does not say what replaces it: `streamViaAcp` still computes `plan` from `planAcpTurn()` and builds `buildDeltaPrompt(context.messages.slice(plan.deltaStart), ...)` whenever `plan.mode === "resume"`, so a resumable turn would send only the delta into a brand-new kiro session that holds no history. The spec names interactive sessions, `/resume`, `fork` and `reload` as cases, so the case is undecided rather than impossible. Fix: decide what happens to `planAcpTurn`/`useResume` and the prompt built for a resumable turn (keep the resume branch, or state that every turn sends the full transcript via `buildPromptFromContext` and what that costs), and say what `recordAcpSession`/`dropAcpSession` bookkeeping does per turn.
- [D2] "Why this is safe:": the safety argument covers four contexts for the unref (during a turn, mid-turn bridged calls, chat transport, interactive pi) but never argues the context the per-turn remount obviously reaches - a second and later turn on the same child, where §5e.3 shows kiro still calls the retired port - and names no test tying that invariant to a check. Fix: argue the multi-turn (and subagent) context for the remount, or drop the remount, and tie the one-URL-per-child invariant to the test that would catch its breakage.
- [D6] "Also close the bridge when a turn settles, so a listener can never outlive": this is a second, separable concern - a redesign of the bridge and ACP session lifetime - bundled into a patch-level hang fix that the spec says the unref already resolves ("the unref fixes the hang without touching either"). Fix: ship the `httpServer.unref()` plus startup-gate keepalive as one PR, and spec the lifetime redesign separately against §5e.3.
- [D5] "- Target release: pi-kiro-agent 0.4.1 (patch)": the bump is declared but no reason is given against the table in `docs/releasing.md` (that nothing a user types or sets changes meaning). Note that removing session resume is a user-noticeable behaviour change, which that table places at minor. Fix: state the reason for the chosen bump, and recheck it against the behaviour the Approach actually changes.
- [D4] "- **Per-turn bridge:** drive two turns on one fake child and assert that each": the riskiest part of the change - a second turn's bridged tool call after the bridge has been remounted on a new port - is only ever exercised against a fake `getBridge`, which cannot show whether the real kiro client follows the new URL. Fix: add a gated live case that makes a bridged tool call on turn 2 after a remount, with `PI_KIRO_TRACE` asserting `bridge.call`/`bridge.result` on the new port.
