## Findings
- [D2] "Each accepted connection is its own referenced socket for its lifetime": the spec argues only the safe direction of this claim (an in-flight call cannot be cut short) and never says what ends that socket's lifetime, so the case it is fixing - a one-shot run whose turn actually used the bridge - rests on an unargued assumption that no accepted connection outlives the response (HTTP keep-alive on the loopback MCP connection would re-create the hold the server unref removes). Fix: state the mechanism that releases the accepted socket (kiro closing it, or the server's `keepAliveTimeout`), bound the extra delay it can add, and tie it to the criterion 2 live case.
- [D5] "Target release: pi-kiro-agent 0.4.1 (patch)": the bump is declared but not justified - the spec never cites the bump table in `docs/releasing.md` or says why this change is a patch rather than a minor, which matters because that table counts "any behaviour change a user could notice" as a minor. Fix: name the table row and the reason (bug fix only; no `PI_KIRO_*` variable, model id, command grammar or floor changes meaning), and add the lockfile resync that `docs/releasing.md` "Cutting a release" step 5 requires alongside the `package.json` bump.
