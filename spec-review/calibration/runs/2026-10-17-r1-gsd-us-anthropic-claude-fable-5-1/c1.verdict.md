## Findings
- [D3] "Then remove the resume branch of `resolveSession()`, so every turn takes the divergence branch: it retires the session, mounts a fresh bridge through `ensureChildBridge()`, and advertises the new URL to kiro in that turn's `session/new`.": this is the exact mechanism `docs/design/acp-transport.md` §5e.3 documents as the bug it fixed (kiro keeps the MCP client it built at the first `session/new`, so a new bridge port advertised on a later `session/new` is never used and every bridged call from turn 2 on fails on the dead port); the spec overturns that documented decision while claiming to preserve it and proposes no supersession. Fix: a new spec must either drop the per-turn close/remount and the resume-branch removal entirely (the `unref()` plus the startup-gate keepalive already fix the hang, as the spec's own Root cause shows) or explicitly supersede §5e.3 with live evidence that kiro rebuilds its MCP client on each `session/new`, and update the §5e.3 test and design section accordingly.
- [D3] "The per-child bridge URL invariant (§5e.3) is preserved.": Goal item 3 contradicts the Approach, which closes the bridge on every turn and mounts a new one with a new port for the next. Fix: remove the per-turn bridge change, or reword the goal to say the invariant is being replaced and why.
- [D3] "Changing the idle-timeout default or the bridge URL lifetime model. Unchanged, no follow-up: the unref fixes the hang without touching either.": the Out of scope sentence is contradicted by the Approach, which changes the bridge lifetime from per child to per turn. Fix: make Approach and Out of scope agree; if the lifetime model stays per child, delete the per-turn close.
- [D3] "The §5e.3 tests (one URL per child across a session reset) pass unchanged.": the existing test `keeps one bridge URL across a divergence reset, so kiro never calls a dead port` asserts one mount, `close` never called and the same URL on both `session/new` calls; the Approach's `close("turn-end")` and remount per turn fail all three. Fix: either drop the per-turn close so the criterion is satisfiable, or state that the test is rewritten and what it will assert instead.
- [D3] "// The server lives as long as the ACP child (§5e.3)": the comment the Approach adds to `serveBridgeHttp()` contradicts the same section's "so a listener can never outlive the turn that needed it". Fix: pick one lifetime and make the code comment, the Approach prose and §5e.3 say the same thing.
- [D2] "Why this is safe:": the argued contexts are a single turn, chat transport and interactive pi; a multi-turn session (interactive or GSD) whose second or later turn calls a bridged tool is a context the per-turn remount obviously reaches, and it is not argued (per §5e.3 those calls fail on the retired port). Fix: argue that context with evidence, or remove the per-turn close so the argument is not needed.
- [D2] "Interactive sessions, `/new`, `/resume`, `fork` and `reload` behave as before.": removing the resume branch means every turn opens a fresh kiro session via `session/new`, which changes the `useResume` prompt-content path (`src/acp-transport.ts`, `promptContent = useResume ...`) and the `acp.prompt.send mode=resume` behaviour; the spec asserts no change without arguing it or naming a test. Fix: either keep the resume branch, or argue why a fresh session per turn preserves prior behaviour and tie it to a test.
- [D6] "Close the bridge when each turn settles, and mount a fresh one for the next turn.": this and the resume-branch removal are a session-model redesign interleaved with the one-line `unref()` fix; they cannot be reviewed apart and the redesign needs its own spec and PR. Fix: scope this spec to the `unref()` and the startup-gate keepalive; move the bridge-lifetime change to a separate spec.
- [D5] "Target release: pi-kiro-agent 0.4.1 (patch)": the choice is not reasoned against the table in `docs/releasing.md`, and as written the Approach contains a user-noticeable behaviour change (fresh kiro session every turn, new bridge URL every turn), which that table classes as a minor, not a patch. Fix: state the reason per the table; once the spec is reduced to the unref fix, "bug fix, nothing a user types or sets changes meaning" justifies the patch.
- [D4] "**Per-turn bridge:** drive two turns on one fake child and assert that each mounted its own bridge and that the first was closed when its turn settled": a fake child cannot show whether kiro keeps or rebuilds its MCP client across `session/new`, which is the property §5e.3 found live-only; no live multi-turn bridged-call case is planned. Fix: add a `PI_KIRO_LIVE=1` case with two turns where the second calls a bridged tool, asserting `bridge.result` with `isError=false`, or drop the per-turn remount.
