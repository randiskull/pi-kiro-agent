## Findings
- [D1] "The bridge probably holds the loop open. `serveBridgeHttp()` (`src/bridge.ts`) starts an HTTP server, and an open server is a likely reason a Node process stays alive.": the cause is hedged ("probably", "likely") although the spec's own evidence settles it: the `process.getActiveResourcesInfo()` snapshot shows a single `TCPServerWrap` on the `bridge.serve` port, and the `PI_KIRO_BRIDGE=off` control exits 0. Fix: state the cause as settled, naming the mechanism (the `httpServer` created in `serveBridgeHttp()` is listening and referenced, and no code path on the one-shot exit route calls its `close()`), and cite the snapshot and the bridge-off control as the evidence that rules out the child and its pipes.
- [D1] "The bug was latent in 0.3.0, where ACP was opt-in, and became visible when 0.4.0 made ACP the default.": provenance is given by release, not by the change that introduced it. Fix: cite the commit that made ACP the default (the 0.4.0 cut, `791cab9`) and the commit that introduced the referenced listener in `serveBridgeHttp()`, so a reader can confirm the listener predates the default switch.
- [D2] "**Chat transport:** the bridge is per turn and closes with the turn, and the `kiro-cli chat` child stays referenced while it runs. Unref changes nothing there.": `serveBridgeHttp()` is shared by both transports, so the unref reaches the chat path, but this context is argued without a test that would catch its breakage. Fix: name an existing `test/stream-adapter.test.ts` case that asserts the chat child is referenced for the turn's duration, or add one, and list it under criterion 4.
- [D3] "`docs/design/acp-transport.md` §5e.3,": the design doc's §5 risks table already documents the one-shot-exit risk and the `setChildKeepalive` mechanism this spec extends, and that row is neither cited nor updated. Fix: cite §5 (the row on the host process not exiting after a one-shot turn) in Related and in Root cause, and add a step to amend that row so it names the bridge listener as the second handle.
- [D5] "- Target release: pi-kiro-agent 0.4.1 (patch)": the bump is chosen but the reason per the `docs/releasing.md` table is not stated. Fix: add one sentence: a bug fix that changes no user-visible surface (no command, model id, `PI_KIRO_*` variable or floor moves), hence patch.
