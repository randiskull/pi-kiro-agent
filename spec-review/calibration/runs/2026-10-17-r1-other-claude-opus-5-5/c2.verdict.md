- [G1] "Mechanics (pick the lightest that satisfies Step 0):": the wiring is left as a choice, with no selection. It could be a `package.json` with `pi.extensions` or a re-export `index.ts`, placed globally (`~/.gsd/agent/extensions/pi-kiro/`) or per project (`<project>/.gsd/extensions/pi-kiro/`). Fix: pick one shape and one location, and give the exact file contents the docs will tell users to create.
- [G1] "pointing at the installed/pinned package": the spec never decides where the package is installed for GSD, or how `export { default } from "pi-kiro-agent"` resolves from `~/.gsd/agent/extensions/pi-kiro/`, which has no `node_modules` above it with `pi-kiro-agent` in it. Fix: state the install location and the resolution path, for example an absolute path into `~/.pi/agent/npm/node_modules/pi-kiro-agent/src/index.ts` or a stated `npm install` into the wiring directory, and say what happens when it does not resolve.
- [G1] "detect host capabilities and degrade (skip a bare-pi-only convenience)": the degrade path does not say what is skipped, which capability is detected, or what the user sees. Fix: name each bare-pi-only surface (for example `src/subagent-wiring.ts` writing `~/.pi/agent/agents`, and `src/bridge.ts` calling `host.getAgentDir()`), and give the behaviour under GSD for each one.
- [G2] "Negative control first (per repo engineering rule):": the rule is not named, so a reader cannot open it. Fix: cite the source, for example `docs/releasing.md` "Citing a test, and when a fix may waive one", or drop the attribution.
- [G2] "referenced in older steering notes": this credits an unnamed source, the case the rubric fails explicitly. Fix: name the notes and their location, or remove the reference.
- [G2] "per repo convention - no em dashes or smart quotes in": no repo document states this convention. The only ASCII rule in the checkout is one test (`test/identity.test.ts`, "is ASCII-only") for the identity string. Fix: cite that test and its scope, or state the rule as a new decision of this spec.
- [G3] "confirm it **fails** (provider not registered / load": the expected failure is an either/or with no mechanism. Step 0 says the factory and manifest are "Already satisfied", and the test builds its own `extensions/pi-kiro/` wiring in a temp home, so nothing explains why it would fail before the change. Fix: say what the check runs against today (for example GSD discovery over a temp agent home with no wiring), the exact failure (no `kiro` provider registered), and why, then say the same check passes once the documented wiring is in place.
- [G3] "**Factory-shape assertion:** test that the extension's registered export is a": this passes on the current code (`src/index.ts` already has `export default async function piKiro`), so it is not a negative control, and the spec gives no expectation for "before". - [D1] "## Root cause": the mechanism is traced to GSD's `getAgentDir`/`discoverAndLoadExtensions` at v1.22.0. It does not explain why a binary named `pi` was bound to GSD's agent home in that shell, which is why the failure is visible now, and no control rules out other in-repo gaps under GSD. Fix: explain the `pi`-to-GSD binding seen in the spike, and list the repo code that assumes pi's home, then rule each one in or out.
- [D2] "Provider registration must not depend on": this is asserted with no argument. The spec does not consider the bare-pi-only surfaces the change obviously reaches: `src/subagent-wiring.ts` hardcodes `~/.pi/agent/agents` (so `/kiro-subagents` under GSD would write into pi's home, against Goal "must not ... interfere with the other host's extension set"), and `src/bridge.ts` imports `@earendil-works/pi-coding-agent` and calls `host.getAgentDir()`. Fix: list each one as an invariant, argue it for the GSD host, and tie each to a test.
- [D2] "## Risks and notes": the spec does not argue the context where both hosts run at once: the shared `~/.kiro/agents` bridge profiles (`src/kiro-bridge.ts`) and the activation-time orphan reaper (`src/orphan-reaper.ts`) sweeping kiro-cli children while another host is live. Fix: either add `@opengsd/gsd-pi` at a pinned version as a devDependency and load through its loader, or state that the stand-in is a proxy and move the GSD proof into the gated live test.
- [D4] "**Live smoke (gated, `PI_KIRO_LIVE=1`):**": the spec does not say what environment the live test needs: the GSD version installed, `GSD_CODING_AGENT_DIR`, the wiring in place, and what to strip, such as pi's own `~/.pi/agent` extension set so a pass cannot come from the wrong host. Fix: list the required environment and what is stripped.

Fix: add all four.
