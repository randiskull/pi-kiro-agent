## Findings
- [G2] "6ea0517 (v0.3.0) moved it to the **child** (`childAbort`)": no commit 6ea0517 exists in the repository (`git log 6ea0517` reports an unknown revision); the commit that introduced `childAbort` and ships in v0.3.0 is 6ea0510 ("fix(acp): keep one bridge URL per child so a session reset can't strand kiro"). Fix: cite 6ea0510, in both places it appears.
- [G2] "`serveBridgeHTTP()` never `unref()`s it (`src/bridge.ts`, after": the function in `src/bridge.ts` is `serveBridgeHttp` (line 744), and nothing in `src/` or `test/` is named `serveBridgeHTTP`. Every mention in Root cause, Approach, Acceptance criteria and Verification plan is a case near miss of the real symbol. Fix: rename all of them to `serveBridgeHttp`.
- [D2] "**Bridged calls arrive only mid-turn.** Each accepted connection is its own referenced socket for its lifetime, so an in-flight tool call keeps the process up until it is answered.": the argument never covers the case where an accepted socket outlives the call. If kiro's MCP HTTP client keeps the connection alive after a bridged call, that referenced socket holds the host open after the turn, until the server's keep-alive timeout closes it. The spec neither says how long that delay can be nor ties a test bound to it. Fix: state that idle keep-alive sockets close after Node's `keepAliveTimeout`, so the extra delay is bounded, and have the bridged-tool live case assert an exit bound that would catch a socket that never closes.
- [D2] "**Interactive pi** keeps its own references (TTY and stdin), so it is unaffected.": the interactive and chat-transport contexts are argued but not tied to any test, and the GSD headless host named in Goal is not argued at all. Fix: name the test that would catch a regression in each context, or explain why each needs none.
- [D3] "`docs/design/acp-transport.md` §5e.3,": the spec reopens the one-shot exit problem that `docs/design/acp-transport.md` §5 (Risks & open questions, the row "Host process cannot exit after a one-shot turn") records as solved by `setChildKeepalive` alone. It does not cite that row, and it does not say the row has to be updated to mention the bridge listener. Fix: cite §5 and add the design-doc row update to In scope.
- [D4] "spawn the real `pi -p` with ACP and the bridge enabled.": the live test does not say what environment it needs. It needs a kiro seat, a `pi` binary to spawn, and, above all, an agent home with at least one extension whose tools are bridged. Root cause shows that a clean home bridges no tools and listens on nothing (the 8ec09e2 control), so without that requirement this regression test passes on the unfixed code. Fix: name the required extension (for example the one providing `rpiv_todo`), state how the test gets it into the agent home, and have the test fail, not skip, when no `bridge.serve` trace is emitted.
- [D5] "Target release: pi-kiro-agent 0.4.1 (patch)": no reason is given for the patch choice, and `docs/releasing.md` is not cited for it. Fix: say that it is a bug fix in which nothing a user types or sets changes meaning, which is the patch row of the `docs/releasing.md` table.
- [D5] "CHANGELOG `## 0.4.1` → `### Fixed` describes the symptom": `docs/releasing.md` puts `### Fixed` bullets under `## Unreleased` (that is where the citation check runs) and has the cut rename it to `## X.Y.Z - YYYY-MM-DD`. `CHANGELOG.md` already has an `## Unreleased` with #58 `### Fixed` bullets, and the spec does not say whether 0.4.1 is cut from that section and so ships those bullets too. Fix: say that the bullet goes under `## Unreleased` / `### Fixed`, and that the release step renames `## Unreleased` to `## 0.4.1 - <date>`, including the existing #58 entries.
