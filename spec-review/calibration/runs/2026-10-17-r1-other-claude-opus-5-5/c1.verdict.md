## Findings
- [D3] "`ensureChildBridge()`, and advertises the new URL to kiro in that turn's": closing the bridge per turn and advertising a new URL in each turn's `session/new` is exactly the defect `docs/design/acp-transport.md` §5e.3 fixed (kiro keeps the MCP client it built for server `pi` pointed at the first port and ignores the new URL), and it overturns that section's decision that "the bridge is mounted once ... and both the new-session and divergence branches reuse it" without proposing to supersede it. A new spec would have to drop the per-turn close and the resume-branch removal (the `httpServer.unref()` plus the startup-gate keepalive alone fix the hang), or else supersede §5e.3 with evidence that kiro now honours a changed URL. Fix: delete the "Also close the bridge when a turn settles" paragraph and its In-scope bullet and criterion 3 clause.
- [D3] "before. The per-child bridge URL invariant (§5e.3) is preserved.": Goal 3 says the per-child URL invariant is preserved, but the Approach mints a new bridge on a new ephemeral port every turn, which breaks it. Fix: make the Approach keep one bridge per child, as Goal 3 states.
- [D3] "The §5e.3 tests (one URL per child across a session reset) pass unchanged.": `test/acp-transport.test.ts` "keeps one bridge URL across a divergence reset, so kiro never calls a dead port" asserts a single advertised URL across two sessions; a per-turn bridge advertises two, so this criterion contradicts the Approach. Fix: keep the per-child bridge so the criterion holds, or stop claiming the test passes unchanged.
- [D3] "The existing "event-loop keepalive" tests pass unchanged.": the "re-references the child for a second turn" test scripts one `session/new` and then two prompts on the same session; removing the resume branch makes the second turn send another `session/new`, so the test cannot pass unchanged. Fix: keep the resume branch.
- [D3] "Unchanged, no follow-up: the unref fixes the hang without touching either.": Out of scope says the bridge URL lifetime model is unchanged, while In scope says "Close the bridge when each turn settles, and mount a fresh one for the next turn.", which changes it from per child to per turn. Fix: remove the per-turn bridge from In scope and Approach.
- [G1] "branch: it retires the session, mounts a fresh bridge through": removing the resume branch of `resolveSession()` leaves the prompt contract open: `planAcpTurn()` still returns `mode: "resume"` with a `deltaStart`, and `useResume` (src/acp-transport.ts) still drives what is sent, so the spec does not decide whether a now-fresh session gets the full transcript or only the delta. Fix: drop the resume-branch removal; if it stays, say what `session/prompt` sends on every turn and how `planAcpTurn` / `recordAcpSession` change.
- [G1] "(`rpiv_todo` or any `pi` MCP tool)": the bridged tool that criterion 2 and the live test depend on is left as a choice, and the live test's "a prompt that forces one bridged tool call" names neither prompt nor tool. Fix: name the one tool (for example `rpiv_todo`), the extension that has to be installed for it, and the prompt.
- [D2] "Why this is safe:": the safety argument covers only the unref. The per-turn bridge close and the move to a fresh session on every turn (which reach interactive multi-turn sessions, `/resume`, fork and subagent sessions) get no invariant, no argument and no test, although §5e.3 documents how this breaks bridged calls after the first turn. Fix: drop those changes, or argue each context and tie each to a test.
- [D2] "**Interactive pi** keeps its own references (TTY and stdin), so it is unaffected.": the unref may not change interactive pi, but the per-turn bridge recycling and the resume-branch removal in the same Approach do change it (every turn becomes a fresh kiro session on a new port), so "unaffected" is asserted, not argued. Fix: limit the Approach to the unref and the startup-gate keepalive, or argue the interactive case for the full change set.
- [D4] "spawn the real `pi -p` with ACP and the bridge enabled.": the live test does not say what environment it needs beyond the strip list: a kiro seat and network, `kiro-cli` on PATH, an installed extension that provides the bridged tool, and which `pi` binary is resolved (the spike's `pi` was GSD's binary, which stripping variables does not fix). Fix: list those preconditions and resolve `pi` from this repo's devDependency rather than PATH.
- [D5] "Target release: pi-kiro-agent 0.4.1 (patch)": the patch bump is not justified against the `docs/releasing.md` table, and the spec does not say that the 0.4.1 cut also ships the existing `## Unreleased` entries (#58). Making every ACP turn a fresh kiro session would be a behaviour change a user could notice, which the table calls a minor. Fix: state the table row and the reason, and say what else the cut contains.
- [D6] "Also close the bridge when a turn settles, so a listener can never outlive": the hang fix (unref plus startup-gate keepalive) is mixed with a defensive redesign of bridge and session lifetime that is not needed for the fix, and the two cannot be reviewed apart. Fix: cut the redesign or move it to its own spec.
