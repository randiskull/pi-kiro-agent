## Findings
- [G1] "pick the lightest that satisfies Step 0": Approach lists two wiring mechanics (a `package.json` whose `pi.extensions` points at the installed entry, or a one-line `index.ts` that re-exports the installed package's default factory) and hands the choice to the implementer rather than deciding. Fix: pick one mechanic and specify its exact contents; keep the other as a note under Out of scope or Risks if useful.
- [G1] "~/.gsd/agent/extensions/pi-kiro/` (global) or `<project>/.gsd/extensions/pi-kiro/` (project-local)": Approach names two install locations for the wiring subdirectory without saying which is the shipped/documented one, or that both are supported with specified semantics. Fix: name one as the primary documented path, or state explicitly that both are supported and give the discovery precedence between them.
- [G1] "skip a bare-pi-only convenience": the degrade path names no specific pi-only global/singleton the extension references and no specific convenience to skip, so the fallback's actual contents are undecided. Fix: name the specific host-surface check (e.g. the `ExtensionAPI` member or module-level global) and the exact code path that is skipped when it is absent.
- [G3] "provider not registered / load error": the parenthetical offers two alternative mechanisms for one check's failure, and the spec does not settle which one the pre-fix check must fail with; "the right reason" is left implicit. Fix: name the single mechanism the GSD-home load test is expected to fail on pre-fix (either "the kiro provider is not among the registered providers because GSD never discovered the package" or a specific throw at load time), and remove the alternative.
- [G4] "Under a GSD home, loading pi-kiro-agent does not alter or break GSD's own extension set": behaviour criterion with no Verification plan step that would produce evidence of it; the Verification plan's "Bare-pi regression", "GSD-home load", "Live smoke" and "Factory-shape assertion" all assert pi-kiro-agent's own loading, not that GSD's bundled extensions continue to load unchanged. Fix: add a verification step that loads a GSD agent home containing pi-kiro-agent plus at least one GSD-bundled extension fixture and asserts both load without new errors.
- [G5] "The transport/parsing internals (ACP vs chat) - unaffected by host scoping.": the item names no destination (no spec, issue or owner) and does not say it is dropped, unchanged or has no follow-up; "unaffected by host scoping" is a reason, not a disposition. Fix: add a disposition, e.g. "unchanged, no follow-up: host scoping does not touch the transport layer."
- [D5] "## Risks and notes": the spec names no target version with a reason tied to `docs/releasing.md`, no CHANGELOG section or `### Fixed` bullet (with a test citation or waiver), and no workaround for users of the affected released version (0.4.0) who are hitting the GSD failure today; none of the D5 anchor items are present. Fix: add a release-operability section that picks the bump per the `docs/releasing.md` table with the reason, names the CHANGELOG subsection and `### Fixed` bullet it will cite its test from, and gives a workaround (e.g. "run under bare pi until this ships") for users on 0.4.x.
