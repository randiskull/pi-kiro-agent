## Findings
- [D3] "mounts a fresh bridge through `ensureChildBridge()`, and advertises the new URL to kiro in that turn's `session/new`.": this overturns the §5e.3 design decision (one bridge URL per child, fixed when kiro first learns it at `session/new`; `ensureChildBridge` lazy-mounts via `acpEntry.bridgePromise ??=` and both branches reuse it) without saying so. §5e.3 states kiro "keeps the MCP client it already built for the server named `pi`" across successor sessions, so a per-turn remount advertises a URL kiro will ignore and bridged tool calls on turn 2+ of an interactive session fail on the retired port — the exact bug §5e.3 fixed, re-introduced at turn boundaries. Fix: a new spec must either preserve the per-child invariant (keep the fix to `httpServer.unref()` plus the startup-gate keepalive, drop the close-the-bridge-per-turn and remove-resume-branch pieces), or explicitly propose to supersede §5e.3 with the mechanism by which kiro will rebuild its MCP client on a successor `session/new`.
- [D3] "The per-child bridge URL invariant (§5e.3) is preserved.": contradicted by the Approach, which closes `entry.bridge` and clears `entry.bridgePromise` after each `session/prompt` settles and makes "every turn takes the divergence branch", so each turn mounts a new bridge on a new ephemeral port — a per-turn URL, not a per-child one. Fix: reconcile Goal with Approach. If the invariant is actually preserved, do not close/clear the bridge across turns; if the Approach is intended, drop this sentence and name the change in Scope.
- [D3] "Unchanged, no follow-up: the unref fixes the hang without touching either.": the Approach does change the bridge URL lifetime model (from per-child, via `acpEntry.bridge ??=`, to per-turn, via `entry.bridge?.close("turn-end")` plus clearing both `entry.bridge` and `entry.bridgePromise`). "Unchanged" is false under this spec. Fix: either narrow the Approach to the unref plus the startup-gate keepalive, leaving the bridge URL lifetime model actually unchanged, or move it to In scope and argue the change.
- [D3] "The §5e.3 tests (one URL per child across a session reset) pass unchanged.": the §5e.3 test in `test/acp-transport.test.ts` ("keeps one bridge URL across a divergence reset, so kiro never calls a dead port") asserts both sessions saw the same URL across a divergence reset; the Approach makes every divergence remount a fresh bridge on a fresh port, so that test would fail. Fix: keep the per-child bridge so the regression test still passes, or state that the test must be rewritten and specify the replacement invariant.
- [D2] "**Interactive pi** keeps its own references (TTY and stdin), so it is unaffected.": the safety argument for interactive pi covers only process lifetime; it does not argue the correctness context — a bridged tool call on turn 2+ when the bridge URL has changed between turns while kiro's MCP client is pinned per §5e.3. This reachable context is asserted ("behave as before") but not argued at the mechanism level. Fix: either argue the mechanism that keeps bridged tool calls working across turns under the proposed changes, or restrict the change so the §5e.3 mechanism continues to carry the invariant.
