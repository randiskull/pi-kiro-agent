## Findings
- [G1] "Mechanics (pick the lightest that satisfies Step 0):": The spec names two wiring mechanisms (a `package.json` whose `pi.extensions` points at the built entry, **or** a one-line `index.ts` that re-exports the default factory) and two locations (global `~/.gsd/agent/extensions/pi-kiro/` **or** project-local `<project>/.gsd/extensions/pi-kiro/`) without selecting either. "pick the lightest" hands the decision to the implementer. Fix: choose one mechanism and one location; move the other to Out of scope or Risks as a noted alternative.
- [G1] "detect host capabilities and degrade (skip a bare-pi-only convenience)": No pi-only global or singleton is identified, so the implementer cannot know what to detect or what to skip. The same section says "Already satisfied by this repo" for the factory shape, leaving the scope of hardening undefined. Fix: either name the specific pi-only surfaces that need guarding and the degradation for each, or state that none were found and remove the hardening commitment.
- [G3] "before the fix, add the GSD-home load test and confirm it fails (provider not registered / load error)": Two problems. First, the stated failure reason offers two alternative mechanisms ("provider not registered / load error") rather than one settled mechanism. Second, the spec states "The factory shape and manifest field are already GSD-compatible; the only missing thing is that nothing places this package under a GSD extensions/ directory," and the GSD-home load test creates that wiring directory as its own setup, so the test's setup supplies the condition the fix exists to provide — the test would pass before any code change. Fix: state a single failure mechanism; identify the code change (not test setup) whose absence makes the check fail and whose presence makes it pass, or reframe the negative control around the Option C hardening if that is what transitions the test.
- [G4] "Under a GSD home, loading pi-kiro-agent does not alter or break GSD's own extension set": This is a behaviour criterion (GSD's bundled extensions still load) with no Verification plan step that produces evidence for it. The GSD-home load test uses a temp agent home with only pi-kiro in it, so it never loads GSD's own extensions alongside. Fix: add a VP step that loads pi-kiro-agent in the presence of at least the GSD extensions named in Root cause (claude-code-cli, cursor-cli, google-cli, gsd, cmux) and asserts they all still load, or demote AC4 to a documentation criterion stating what file must say they coexist.
- [G5] "The transport/parsing internals (ACP vs chat) - unaffected by host scoping.": "unaffected" is a reason (describes the item) rather than a disposition. The item names no owner, does not say it is dropped or unchanged, and states no follow-up. Fix: add a disposition, e.g. "unchanged, no follow-up" or "dropped."
- [D1] "## Root cause": The mechanism is traced to GSD's discovery code (specific functions, discovery paths) and is consistent with the observed errors. However, provenance is absent: there is no commit or event that introduced the gap — it was never wired. The third discovery source ("Explicitly configured paths (passed in by the CLI/config)") is listed but not explored as an alternative route, so alternative-ruling is incomplete. Fix: state that provenance is inapplicable (the feature was never present, not regressed) and argue why the explicitly-configured-paths source is not a viable alternative.
- [D2] "does not perturb GSD's own extensions": Safety is asserted without an argument. The spec itself describes the `mergeExtensionEntryPaths` shadowing mechanism (an installed extension keyed by `extension-manifest.json` id can shadow a bundled one), but does not verify that pi-kiro-agent's extension id — or the absence of an `extension-manifest.json` — prevents a collision with any GSD extension. Similarly, "Provider registration must not depend on any bare-pi-only surface" is asserted, but the 14 source files that import `@earendil-works/pi-coding-agent` or `@earendil-works/pi-ai` are not checked against GSD's virtualised aliases. Fix: inventory the extension ids in GSD's extension set and confirm no collision; list the host API calls the extension makes and confirm each exists on GSD's ExtensionAPI at v1.22.0.
- [D3] "## Approach": The spec discusses ACP transport behaviour (Option C: "Keep readiness-gated registration intact") and the GSD-home load test mirrors the e2e that uses `discoverAndLoadExtensions`, but `docs/design/acp-transport.md` is not cited. Fix: cite it by path, or state that the design doc is not touched by this change.
- [D4] "Live smoke (gated, PI_KIRO_LIVE=1)": The live test is gated but does not state what environment it needs beyond the gate variable (which GSD binary, which kiro-cli version, whether GSD_CODING_AGENT_DIR must be set, what to strip from captured output). Fix: list the environment requirements and any output-stripping needed for deterministic comparison.
- [D5] "## Risks and notes": No target version is chosen per `docs/releasing.md`; no CHANGELOG section or subsection is named; no `### Fixed` bullet is drafted; no workaround is stated for users on currently-released versions who need kiro under GSD today; no rollback or migration discussion appears. The package ships `docs/` and `README.md` (per the `files` allowlist), so the documentation changes are published content and need a version. Fix: choose a version bump (patch or minor per `docs/releasing.md`), name the CHANGELOG subsection and draft the bullet, and state the interim workaround (users can create the wiring directory manually today).
