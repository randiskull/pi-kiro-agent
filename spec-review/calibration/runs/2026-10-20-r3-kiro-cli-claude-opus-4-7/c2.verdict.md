- [G1] "Mechanics (pick the lightest that satisfies Step 0):": the Approach then names two mechanisms for the GSD wiring entry (a `package.json` whose `pi.extensions` points at the installed package's built entry, OR a one-line `index.ts` that re-exports the default factory) and hands the choice to whoever implements it. Fix: choose a single wiring form, specify its exact contents (filename, manifest field or entry file, resolution path for `pi-kiro-agent`), and move the other mechanism out of the Approach.
- [G1] "detect host capabilities and degrade (skip a bare-pi-only convenience) rather than failing the whole load": the degrade path does not say which bare-pi-only convenience is skipped under GSD, how the host is detected, or what the user-visible behaviour is in the degraded case. Fix: name the specific convenience (API, surface or feature) that is skipped, state the detection check, and state the degraded behaviour.
- [G2] "**ASCII-only** in any host-read string (manifest fields, extension name, command ids) per repo convention": the "repo convention" source is not named, so a reader cannot open it to confirm the rule exists and says what the spec claims. Fix: cite the convention by path (e.g. a steering file, `docs/...`, or an existing lint rule) so the source is openable from this checkout.
- [G2] "**Negative control first (per repo engineering rule):**": the "repo engineering rule" is not named, so there is no openable source for the rule the step credits. Fix: cite the rule by path (steering file, repo doc or lint check) that states the negative-control-first requirement.
- [G2] "the installed build is newer than the v1.2/v1.3 referenced in older steering notes": "older steering notes" names no file, so a reviewer cannot resolve the claim. Fix: cite the specific steering file(s) by path, or drop the comparison; a gitignored note needs its observation restated in the spec itself.
- [G4] "Under a GSD home, loading pi-kiro-agent does not alter or break GSD's own extension set (GSD's bundled extensions still load; the cmux message, if any, is GSD-pre-existing and unchanged by this package).": this is a behaviour criterion but no Verification plan step produces evidence that GSD's bundled extensions still load. Fix: add a Verification plan step that loads a GSD-shaped `extensions/` directory containing representative GSD-bundled stand-ins (or the live GSD set under the gated live smoke) alongside the wiring entry, and asserts the other extensions still load.
- [G5] "The transport/parsing internals (ACP vs chat) - unaffected by host scoping.": "unaffected by host scoping" is a reason, not a disposition - it describes the item instead of saying where it goes or that nothing follows. Fix: add one of `dropped`, `unchanged`, "no follow-up", or a named spec/issue/owner alongside the reason.
