- [D1] "### What the reader does with v3's payloads today": The Problem section traces the reader's code paths and states what the reader would do with v3 payloads as claims derived from code reading ("The reader draws a row for v3's internal call, named `kiro_unknown` with empty arguments, on every v3 turn"), but no command is run against the reader and no output is shown. The design doc's §3.3/§3.7 measurements are cited but they measure kiro-cli's wire output, not the reader's behaviour with that wire output. The rubric requires the spec itself to show "a command that was run, an output or a number it produced, and the ref" for a 3 or 4, and the anchor explicitly says "a Problem that names the right code and states its findings as claims is a 2, however precise those claims are and however well they hold up." Fix: add a measurement to the Problem section — for example, feed the §3.3 internal-call payload into `createStreamJsonReader()` in a one-off script or test, show the output (the `kiro_unknown` row), and record the ref. That makes the current behaviour observed, not only predicted.
