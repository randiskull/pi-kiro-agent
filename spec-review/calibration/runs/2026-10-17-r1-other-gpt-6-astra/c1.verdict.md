## Findings
- [D3] "Close the bridge when each turn settles, and mount a fresh one for the next turn.": This reinstates the defect fixed by 6ea0510 and documented in `docs/design/acp-transport.md` section 5e.3: a second `session/new` on the same child does not replace kiro's cached MCP client for `pi`, so closing the original endpoint strands subsequent calls on its dead port. The spec neither proposes to supersede that decision nor provides evidence that the protocol now permits replacement; instead its Goal and Out of scope explicitly promise to preserve it. This is why the spec should not be built as framed. Fix: a replacement spec should retain the child-scoped bridge and session reuse, restricting this fix to listener unref and the startup keepalive gap. A different lifetime design requires an explicit, evidence-backed supersession of section 5e.3.
- [D3] "The §5e.3 tests (one URL per child across a session reset) pass unchanged.": This acceptance criterion contradicts the required per-turn bridge test. `test/acp-transport.test.ts:1385-1450` explicitly asserts one mount, equal URLs across two sessions, and no close; the proposed implementation and new test require two mounts and a close. Both cannot pass. Fix: remove the per-turn remount requirement and its test so the unchanged regression remains a valid acceptance gate.
- [G1] "resume branch of `resolveSession()`, so every turn takes the divergence": The spec does not decide how resetting every session changes prompt planning and ledger updates. In `src/acp-transport.ts:1078-1084`, `useResume` is computed before `resolveSession`; it independently selects a delta prompt at lines 1210-1212 and advances the old session at lines 1276-1280. Removing only the resolver's resume branch therefore sends a delta to an empty session and advances a discarded ledger entry. Fix: preserve the existing resume path for this fix, or explicitly specify full-context replay and recording of the new session when a reset overrides a resume plan.
- [D2] "**Interactive pi** keeps its own references (TTY and stdin), so it is unaffected.": This argues only that interactive hosts stay alive, not that the newly introduced per-turn session retirement is safe in them. Subsequent interactive turns now lose session continuity and rotate an endpoint kiro caches; the safety argument never addresses that reachable context. Fix: keep the bridge and session lifetime unchanged, or supply a separate safety argument and multi-turn tests for the changed lifetime, including successful bridged calls after the first turn.
- [D4] "spawn the real `pi -p` with ACP and the bridge enabled.": The live setup does not require or provision an installed, bridgeable user-scope tool. The spec itself establishes that enabling the bridge with no captured tools creates no listener, allowing the first live exit check to miss the defect and leaving the forced-tool case dependent on unspecified local installation. Fix: name the required authenticated kiro/pi environment and installed tool package, and assert a nonempty bridge mount before checking exit behavior.
- [D5] "Target release: pi-kiro-agent 0.4.1 (patch)": The target is chosen without a reason against the release table. The proposed removal of session reuse is not merely an event-loop bug fix: it changes observable multi-turn behavior, which `docs/releasing.md` assigns to a minor release. Fix: remove that behavior change and explicitly justify a patch as preserving the existing user contract, or justify and select the release class for the redesigned behavior.
