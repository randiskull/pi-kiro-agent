## Findings
- [D1] "The bridge probably holds the loop open. `serveBridgeHttp()` (`src/bridge.ts`) starts an HTTP server, and an open server is a likely reason a Node process stays alive.": the spec hedges the one claim the entire fix depends on ("probably", "a likely reason") in a case where the evidence to settle it was already in hand and quoted two paragraphs earlier: the `process.getActiveResourcesInfo()` snapshot names the exact resource type (`TCPServerWrap`) and the exact port, matching the `bridge.serve` trace port one-for-one. That observation, read against `serveBridgeHttp()` (verified: it builds the listener with `createServer(...)` and never calls `.unref()` on it, confirmed by reading `src/bridge.ts` lines 744-853), already shows the mechanism rather than merely suggesting it — the hedge is never retracted even though the spec's own Approach section proceeds as if it had been. Fix: drop "probably"/"likely" and state the resolved claim directly, e.g. "the bridge's `TCPServerWrap` is the resource the snapshot names, matching the `bridge.serve` port; `serveBridgeHttp()` never calls `.unref()` on `httpServer`, confirmed by reading the function," citing the line range. This is a one-sentence fix, not a re-investigation: the settling evidence is already quoted in the spec.
- [D1] "The bug was latent in 0.3.0, where ACP was opt-in, and became visible when 0.4.0 made ACP the default.": this provenance claim is stated but not traced to a commit or PR the way the rubric's D1-4 anchor for a defect spec requires ("provenance ... by commit"). `CHANGELOG.md`'s `## 0.4.0` heading (read in this review) does carry a `### Changed` bullet, "Breaking: the ACP transport is now the default," confirming the behavioral claim, but neither that bullet nor the spec names the PR or commit that made the change, only the generic observation. (Other `0.4.0` bullets in the same CHANGELOG section are tagged `(#56)`; this one is not.) Fix: name the PR or commit that flipped the ACP default, so the "latent, now visible" claim carries the same commit/PR-level provenance the anchor asks for.

The diagnosis is otherwise strong: the mechanism is traced to a specific function and call site (`serveBridgeHttp`'s unref'd-`nothing`-ness, confirmed by reading the function), the `setChildKeepalive` unref behavior is correctly described and pinned to an existing test, the `teardownChild` caller enumeration (abort, idle timeout, turn ceiling, stale child, child exit, eviction, failed initialize, test reset) matches the eight call sites found in `src/acp-transport.ts`, and `dispatchMessage`'s unref-on-last-pending-settle is traced precisely to the code that performs it. The two hedge/provenance gaps above are what hold D1 at 2 rather than 3: per the rubric's own anchor, "hedged ... where the evidence to settle it was available" is the level-2 case, not level-3, and here the settling evidence is quoted in the same section as the hedge.
