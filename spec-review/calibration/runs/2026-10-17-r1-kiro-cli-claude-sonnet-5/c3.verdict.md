## Findings
- [G3] "## Verification plan": no step in this section is framed as a negative control. The section lists a server-unref unit test, a startup-gate unit test, a gated live regression, a manual reproduction, and "Full suite last" -- none states a check run against the code **before** the change, that it fails there and why, and that it passes after. The "Observed failure" table ("`pi -p --no-session --model kiro/auto \"Reply: x\"`" / "answer printed, then hangs; killed by the 240 s `timeout`") documents a before-state, but it sits in Observed failure, not Verification plan, and is never tied there to "this is the negative control, it fails for reason X, and now passes." Fix: add an explicit Verification plan bullet, e.g. "Negative control: run the criterion-1 command against the pre-fix tree; it hangs past 120s because `serveBridgeHttp`'s listener is referenced (confirm via `process.getActiveResourcesInfo()` showing `TCPServerWrap`); after the fix the same command exits 0."
- [D2] "**Chat transport:** the bridge is per turn and closes with the turn, and the `kiro-cli chat` child stays referenced while it runs. Unref changes nothing there.": this invariant (the unref is a no-op for the chat transport) is argued but not tied to a test -- no chat-transport test is named that would catch a regression where the unref somehow affected `stream-adapter.ts`'s turn lifetime. Fix: name an existing or new chat-transport test (e.g. in `test/stream-adapter.test.ts` or `test/bridge.test.ts`) that exercises `serveBridgeHttp` under the chat transport's per-turn signal and would fail if the unref broke that path's liveness.
- [D3] "`docs/design/acp-transport.md` §5e.3,": the spec cites only §5e.3, but `## 5. Risks & open questions` (unnumbered sub-letter, just "5") already carries a table row titled "Host process cannot exit after a one-shot turn" documenting the exact `setChildKeepalive` four-handle-unref mechanism the Approach extends -- the design doc's own prior statement of the invariant this fix must preserve.
